#+date: [2026-11-05 周四]
#+filetags: :dida:workflow:

* 这是什么

=dida-workflow.el= 是一个*用户侧自定义层*，不修改 =dida.el= 库，只调用它的底层 API：

- =dida-auth--ensure-async= / =dida-token=：认证（需要刷新时才走网络）；
- =dida-api-list-projects-async= / =dida-api-get-project-data-async=：拉清单与任务；
- =dida-api-get-task-async= / =dida-api-create-task-async= /
  =dida-api-update-task-async= / =dida-api-complete-task-async= /
  =dida-api-delete-task-async= / =dida-api-move-task-async=：写操作；
- =dida-api-task-payload= / =dida-api-payload-from-remote=：构造/合并 payload。

所有网络调用都是异步的（回调链），等待期间不阻塞 Emacs。

工作流（与 [[file:WORKFLOW-RESET.org][WORKFLOW-RESET.org]] 一致）：

| 区 | 文件 | 结构 | 同步 |
|----+------+------+------|
| 日常 | =dida.org= | 一级清单 + 二级任务（任务为叶子） | ✅ 双向 |
| 习惯 | =habit.org= | 重复任务（org-habit / REPEAT_CRON） | ❌ |
| 项目 | 任意 agenda 文件 | 层级任务 | ❌ |

日常区是*活跃列表*：完成/放弃后本地移除，滴答保留历史。
状态只有 待办 / 完成 / 放弃；完成与放弃在滴答侧都算完成。
滴答里的重复任务跳过，重复任务统一放 =habit.org=。
任务从 =dida.org= 剪走时按 =my-dida-out-of-scope-policy= 处理远端任务。

* 快速开始

=dida-workflow.el= 与 =dida.el= 在同一个仓库，并且放在*仓库根目录*。
TomoELPA 用 package-build 构建 dida 包时，默认的 `*.el` 规则会把它一起打包；
装完 dida 后文件就在包目录里（load-path 上），直接 =require= 即可，不需要手动
=load-file= 或额外加 load-path。

** 1. 从 TomoELPA 安装

#+begin_src elisp
(add-to-list 'package-archives
             '("TomoELPA" . "https://tomoemami.github.io/tomoelpa/snapshots/"))
(package-install 'dida)        ; dida-workflow.el 会一起装上
#+end_src

之后：

#+begin_src elisp
(require 'dida)
(require 'dida-workflow)
#+end_src

** 1.1 用 use-package

`dida-workflow` 不是独立包（它是 dida 包里的一个文件），所以加 =:ensure nil=；
dida 加载后它自然在 load-path 上：

#+begin_src elisp
(use-package dida
  :demand t
  :custom
  (dida-client-id "YOUR CLIENT ID")
  (dida-client-secret "YOUR SECRET"))

(use-package dida-workflow
  :ensure nil          ; 不是独立包，别让 package.el 去 ELPA 找
  :after dida
  :config
  (my-dida-auto-sync-mode 1))
#+end_src

完整配置见第 2 节。

如果你直接从 GitHub 用 =:vc= 安装 dida，也一样：package-vc 会把整个仓库
装进包目录，=dida-workflow.el= 在包根目录，load-path 行为一致：

#+begin_src elisp
(use-package dida
  :vc (:url "git@github.com:TomoeMami/dida" :rev :newest)
  :demand t)

(use-package dida-workflow
  :ensure nil
  :after dida
  ...)
#+end_src

** 2. 配置

#+begin_src elisp
(use-package dida :demand t
  :custom
  (dida-client-id "YOUR CLIENT ID")
  (dida-client-secret "YOUR SECRET")
  ;; 推荐 personal API token；也可以继续用 OAuth
  (dida-token-file "~/.emacs.d/didatoken")
  (dida-api-base "https://api.dida365.com")
  (dida-time-zone-offset "+0800"))

(use-package dida-workflow
  :ensure nil
  :after dida
  :custom
  (my-dida-file (expand-file-name "dida.org" "~/denote/org/phone/"))
  (my-dida-state-file (expand-file-name "my-dida-state.eld" "~/emacs-local/"))
  (my-dida-whitelist nil)                 ; nil = 同步所有清单
  (my-dida-out-of-scope-policy 'delete)   ; delete / detach / review
  (my-dida-content-policy 'two-way)       ; two-way / pull-new / off
  (my-dida-sync-repeat-p nil)             ; 重复任务不同步
  (my-dida-archive-file nil)              ; 非 nil 时移除前追加到该文件
  (my-dida-debounce 8)
  (my-dida-idle-interval 300)
  ;; 顺序使用多设备时每台设备都可以开自动同步（任何时刻只让一台 Emacs 在写）
  (my-dida-primary-device-p t)
  :config
  (my-dida-auto-sync-mode 1))
#+end_src

常开设备（例如家里的 server）如果 Emacs 常驻，把 =my-dida-primary-device-p=
设为 nil（或不开 auto mode），只手动同步，避免它在后台和你的笔记本同时写。

** 3. 准备文件

- 建 =~/denote/org/phone/dida.org=，只写 =#+title: 滴答日常=；
  首次同步会自动按远端清单建一级 heading。
- =habit.org= 等其它文件不用动。
- 关键字保持 =待办/完成/放弃=；=等待= 由你自己改成 =待办= + tag，dida-workflow 不处理。

** 4. 先预览再同步

#+begin_example
M-x my-dida-preview
M-x my-dida-sync
#+end_example

首次同步：为白名单清单建 heading（=ensure-project=），把远端任务插成二级任务
（=create-local=）。之后 =my-dida-auto-sync-mode= 会在保存/状态变化后 8 秒、
空闲 300 秒、启动 20 秒后各同步一次（静默）。

* 命令

| 命令 | 作用 |
|------+------|
| =my-dida-sync= | 完整双向同步（会打印统计） |
| =my-dida-preview= | 只打印计划，不写文件、不发写请求 |
| =my-dida-push-heading= | 立即推送当前 heading（新建或更新） |
| =my-dida-detach= | 去掉当前 heading 的 DIDA_* 属性与本地状态；远端不动 |
| =my-dida-set-list= | 把当前任务换到另一个清单（下次同步推 move） |
| =my-dida-review= | 查看冲突/待确认删除 |
| =my-dida-auto-sync-mode= | 全局自动同步开关 |

建议键位：

#+begin_src elisp
(global-set-key (kbd "C-c d s") #'my-dida-sync)
(global-set-key (kbd "C-c d p") #'my-dida-preview)
(global-set-key (kbd "C-c d P") #'my-dida-push-heading)
(global-set-key (kbd "C-c d r") #'my-dida-review)
#+end_src

* 行为细节

** 异步（不阻塞 Emacs）

2.4 起同步全程走 plz 的异步接口（=dida-api-*-async= + 回调链）：

- 自动同步（启动 / 空闲 / 保存 / TODO 变化）和 =M-x my-dida-sync=、
  =M-x my-dida-preview= 都会立即返回，网络等待期间 Emacs 可正常操作；
- 重试退避用 =run-at-time=，不再用 =sleep-for= 阻塞主线程；
- 同一时间只跑一轮：上一轮没结束时新的一轮直接跳过；成功 / 失败 / 异常
  路径都会清理 busy 标志，不会因为一次失败卡死后续同步；
- 等待远端期间如果 =dida.org= 被改过（有未保存修改），本轮直接取消，
  避免用过期快照覆盖用户编辑；
- 汇总消息在结果回来后才出现；静默同步仍然不打扰。

** 状态

- =待办= ↔ status 0；
- =完成= → complete；=放弃= 也 complete（滴答侧没有「放弃」）；
- 远端完成拉回时：如果本地已经是 done 关键字，*保留 完成/放弃 的区别*，只补 CLOSED；
- 本地把 完成/放弃 改回 待办 视为重开：默认只本地重开、不推远端（滴答不支持 uncomplete），
  需要远端也重开时先删滴答任务再 =my-dida-push-heading=。

** 完成与删除

- 本地 完成/放弃 → 完成 outbox：=complete= → 回读 status=2 → 从 =dida.org= 移除；
  失败则保留 heading 并记 pending，下轮重试（不会「完成被撤销」）。
- 滴答完成/删除 → 本地任务消失 → 移除本地（若有未同步本地改动则进冲突）。
- 丢弃完成/删除的区别：日常区是活跃列表，两者结果都是「本地移除」。

** 剪出 dida.org

=my-dida-out-of-scope-policy=：

| 值 | 行为 |
|----+------|
| =delete=（默认） | 删除滴答任务（进滴答回收站） |
| =detach= | 保留滴答任务，只清本地状态 |
| =review= | 进 =my-dida-review= 手动决定 |

一轮内「消失」超过 =my-dida-bulk-threshold=（默认 10）会冻结，只报告不执行。
剪走后项目文件里残留的 =DIDA_TID/DIDA_BASE= 建议 =M-x my-dida-detach= 清掉。

** 标题原文（标签 / 统计 cookie）

- 同步的是 heading 去掉 TODO 关键字和优先级之后的*标题原文*：
  =:tag:= 标签、=[/]= / =[%]= 统计 cookie、链接、强调标记等一律按文本
  原样进滴答任务标题，不会丢；
- 标签只是标题文本，*不映射成滴答标签*：滴答侧会看到
  =买菜 [/] :errand:urgent:= 这样的标题；在滴答里改这段文本，下一轮会
  原样写回 Org（末尾的 =:tag:= 会重新成为 Org 标签）；
- 只去掉 TODO 关键字（待办/完成/放弃，映射到完成状态）和 =[#A]= 优先级
  cookie：标题里不带它们；优先级本身*完全不参与同步*（见下节）。

** 时间（只认 SCHEDULED）

- 只把 =SCHEDULED= 时间同步成滴答的 =dueDate= / =isAllDay=；
  =DEADLINE= *完全不参与同步*，本地留着、推拉都不动；
- 拉回远端日期时只写 =SCHEDULED=，不会把 =DEADLINE= 改成别的；
- 全天任务的 =dueDate= 可能被滴答按 UTC 归一（例如北京时间 11-06 全会返回
  =2026-11-05T16:00:00+0000=）：读回时按 =dida-time-zone-offset=（默认 ="+0800"=）
  换算成当地日期，不能直接截字符串，否则会退一天（2.4.1 修复）；
  如果改过 =dida-time-zone-offset=，请确认它与账号时区一致；
- 优先级、=:tag:= 到滴答标签的映射等 Org 特有属性都不同步：滴答数据只
  接收标题、正文和时间，本地 Org 里的优先级/DEADLINE/其它属性由你自己管。

** 冲突

- 字段级三方合并（标题/正文/状态/日期）；
- 同字段两边改不同 → 进 =my-dida-review=，选「以本地为准 / 以滴答为准」；
- 无 base（新设备）且两边不一致 → 冲突，先以某一边为准收敛。

** 多设备（顺序使用）

你的情况是「同一时间只在一台设备上用 Emacs」，推荐：

- *每台设备都开自动同步*，=my-dida-primary-device-p= 设为 t；
- 关键规则：*不要同时运行两台 Emacs 的自动同步*。换设备前退出旧设备的 Emacs，
  或先 =M-x my-dida-auto-sync-mode= 关掉；
- =my-dida-state-file= 保持本机缓存（=~/emacs-local/=），*不要*放进 Syncthing 目录；
- =my-dida-file= 不用为每台设备手写：从 =my/org-dir1= 这类变量取，
  各设备指向自己那份 Syncthing 副本即可；
- 跨设备一致性靠 org 里的 =DIDA_BASE= 指纹：
  - 未改动的任务在新设备上直接 =agree=，不产生冲突；
  - 只有「两台设备各自改过同一条、且没有同步过」才会进冲突，用 =my-dida-review= 处理；
- 新设备第一次同步：先 =M-x my-dida-preview=，确认没有 =conflict= 再 =my-dida-sync=；
- 离开一台设备前建议跑一次 =M-x my-dida-sync=（或等 8 秒防抖跑完），
  确保 pending 完成/编辑已推到滴答。

*不建议共享 state 文件*：顺序使用也没必要，反而会在 Syncthing 上产生
=*.sync-conflict-*= 副本；每台设备独立 state、靠 =DIDA_BASE= 指纹协作就够了。
代价是极端情况下（两台设备改同一条且未同步）字段级合并退化为冲突，人工选一次即可。

* 已知限制

- 不查询「已完成」窗口：`project/{pid}/data` 正常只返回未完成任务；本层仍显式忽略
  =status 2/-1=（已完成/放弃），*绝不会 create-local 把已完成任务拉回*。
  远端完成与远端删除都表现为「任务从活跃列表消失」，本地处理都是移除；
  本地有未同步改动时进冲突。
- 重复任务不同步（远端 =repeatFlag= 非空整条跳过；本地带 repeater 也不推送）。
- 优先级、=DEADLINE= 不同步（本地保留、推拉都不动）；滴答只接收标题、正文、
  =SCHEDULED= 时间。
- 标签不映射成滴答标签，只作为标题文本同步（见「标题原文」）；
  =items=/提醒/desc 原样保留但不映射。
- 不做项目/清单 CRUD；新清单要在滴答里建，同步会自动补 heading。
- 不批量：一轮同步 ≈ =1 + 清单数 + 写操作数= 个请求；请求异步执行，
  不阻塞 UI，但仍是串行链（一轮内不并发）。
- 正文 =two-way= 时，pull 会覆盖本地正文（只覆盖直属正文，不动子 heading）；
  长纪要/checklist 建议放项目文件，或把 =my-dida-content-policy= 改为 =pull-new=。
- =dida.org= 有未保存修改时跳过本轮（auto-save 一般 2 秒内会保存）。
- 要求 org 关键字里有 =待办/完成/放弃=（=完成/放弃= 要在 =|= 之后），
  否则 =org-todo= 会报错。
- 正文里以 =*= 或 =#+= 开头的行在插入 org 时会变成 heading/关键字；
  日常任务正文请保持短备注（长内容放项目文件）。
- 首轮同步会为所有清单建 heading（=my-dida-whitelist nil=）；清单很多时先设白名单。

* 与库的关系

- =dida.el= 已精简为纯 API 层（认证 / HTTP / 资源函数 / payload / OAuth）；
  旧的兼容层、Org 转换、命令和 2.0 同步引擎已删除（git 历史里还能找到）。
- =dida-workflow.el= 放在仓库根目录，随 dida 包一起分发；
  测试在 =test/test-dida-workflow.el=，不会被打进包。
- 本文件只用 =dida-api-*= 与认证函数；库升级只要这些 API 不变，本层就不用动。
